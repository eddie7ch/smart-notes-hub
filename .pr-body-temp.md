## Problem
Cloud Run terminates TLS and forwards requests to the container with an `X-Forwarded-For` header. Without Express's `trust proxy` setting enabled, `express-rate-limit` logged a validation warning (`ERR_ERL_UNEXPECTED_X_FORWARDED_FOR`) and fell back to keying its rate limit on Cloud Run's internal proxy IP instead of the real caller's IP - meaning every client shared the same rate-limit bucket.

## Fix
Enable `app.set("trust proxy", true)` so Express (and by extension `express-rate-limit`) reads the real client IP from `X-Forwarded-For`.
